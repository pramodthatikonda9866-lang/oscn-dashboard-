📖 5. Code Explanation & OS Core Concepts

Clear, simple explanations for faculty evaluation and viva voce

🧵 1. What is Threading?

A thread is a lightweight unit of execution within a process. Multiple threads share the same process memory and database connections. In this project, each student request runs on its own thread, allowing multiple students to submit requests simultaneously.

🔒 2. What does threading.Lock() do?

threading.Lock() creates a Mutual Exclusion (Mutex) lock primitive. It has only two states: unlocked and locked. It ensures that only one thread can execute the protected critical section at any given moment.

🛡️ 3. What is a Critical Section?

The Critical Section is the portion of code that accesses shared mutable data (lines 13–44 where book availability is checked and updated in SQLite). If two threads enter this section together without synchronization, data corruption occurs.

📥 4. What does lock.acquire() mean?

acquire() attempts to obtain the lock. If the lock is free, the calling thread locks it and enters the critical section immediately. If another thread already holds the lock, the calling thread is paused in a waiting queue until the lock becomes free.

📤 5. What does lock.release() mean?

release() unlocks the mutex, transitioning it from locked to unlocked. This signals waiting threads that the critical section is now free, allowing the next queued thread to acquire the lock and proceed.

✨ 6. Why do we use 'with lock:'?

Using Python's with book_lock: context manager guarantees that acquire() is called before entering, and release() is always called upon exit—even if an error or exception occurs. This completely prevents deadlocks!

⚠️ 7. What is a Race Condition?

A Race Condition happens when competing threads access and modify shared data without adequate coordination. For example, two students both observe 1 copy as "Available" at the exact same time, causing the single physical book to be issued to both students!

⏳ 8. What does join() do?

t.join() pauses the main coordinating program until thread t has fully finished its execution. Calling join() on all threads ensures all student requests have finished before calculating final results and database counts.
