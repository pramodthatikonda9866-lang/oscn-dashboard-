import threading import time available_copies = 3 # Create Mutex Lock mutex = threading.Lock() def issue_book(student_id, use_mutex): global available_copies if use_mutex: # Mutex ON with mutex: if available_copies > 0: available_copies -= 1 print(f"Student {student_id}: BOOK ISSUED") else: print(f"Student {student_id}: NO_COPY_AVAILABLE") else: # Mutex OFF - Race Condition if available_copies > 0: time.sleep(0.1) available_copies -= 1 print(f"Student {student_id}: BOOK ISSUED") else: print(f"Student {student_id}: NO_COPY_AVAILABLE") # Create and execute threads students = [] for i in range(10): t = threading.Thread( target=issue_book, args=(i + 1, True) ) students.append(t) # Start threads for t in students: t.start() # Wait for completion for t in students: t.join()

📝 Explanation of Key Python Statements

Statement Construct Plain English Explanation
import threading Imports Python's standard multithreading library, allowing the application to create and coordinate concurrent student threads.
available_copies = 3 Shared Global Resource: Represents the shared counter of physical book copies available in the library.
mutex = threading.Lock() Creates Mutex Lock: Instantiates a mutual exclusion lock primitive to protect the shared critical section from simultaneous access.
def issue_book(student_id, use_mutex): Defines the thread worker function executed concurrently by each student thread requesting to issue a book.
global available_copies Declares that the function modifies the shared global variable available_copies rather than creating a local variable.
with mutex: Mutex ON (Critical Section): Automatically acquires the lock before entering. Only 1 thread enters at a time; others wait. Automatically releases the lock on exit.
if available_copies > 0: ... -= 1 Availability Check & Issue: Safely inspects and decrements the copy counter atomically under mutex protection.
time.sleep(0.1) (Mutex OFF) Race Condition Demonstration: Without mutex, introduces a delay allowing multiple threads to observe available copies at the same time, causing over-allocation.
students = [] List data structure that stores all spawned Thread objects for centralized tracking.
threading.Thread(target=issue_book, args=(i + 1, True)) Creates an individual thread assigned to execute issue_book for that student with Mutex enabled.
t.start() Starts concurrent execution of the student thread in the operating system scheduler.
t.join() Halts the main coordinator until that specific student thread completes execution, ensuring all 10 students finish cleanly.
💡 Core Concurrency Concepts in This Implementation
threading.Thread() — Creates a new thread representing an individual student's concurrent book issue request.
threading.Lock() — Creates a mutual exclusion (mutex) lock primitive to coordinate shared resource access.
with mutex — Context manager that allows only one thread into the protected critical section at a time, releasing the lock automatically upon exit.
Critical Section — The protected code section where book availability is checked and decremented.
join() — Halts the main coordinator thread and waits for all spawned student threads to finish execution cleanly.

🎓 5. Faculty Evaluation Reference (OS Concepts & Implementation Q&A)

Viva voce guide from Page 13 of the specification
Q: Why import threading?

To create and coordinate concurrent execution threads in Python representing simultaneous student requests.

Q: What does threading.Lock() do?

It creates a mutual-exclusion (mutex) lock primitive. Only one thread can acquire the lock at any instant; all competing threads are put into a waiting state until the lock is released.

Q: What is a Critical Section & Race Condition?

A Critical Section is the code region that accesses shared mutable state (checking book copies and writing transactions). A Race Condition happens when unsynchronized threads interleave reads and writes, resulting in two students obtaining the same physical copy.

Q: Why use 'with book_lock:' context manager?

It guarantees that the lock is automatically released whenever the block exits—even if an unhandled exception or database rollback occurs—preventing deadlocks.

Q: Why combine Python Mutex Synchronization with SQLite Database Transactions?

The mutex protects in-memory concurrent thread execution paths from simultaneous entry, while SQLite ACID transactions and foreign key constraints ensure disk persistence consistency and atomic rollback.
